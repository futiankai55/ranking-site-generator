# Google AdSense 月5万円達成ロードマップ

このドキュメントは、本システム（`ai-tools` など）を使ってAdSense収益 **月5万円** を目指すための計画書。
断言できる保証はない前提で、逆算した目標数値とフェーズごとのアクション・使用コマンドをまとめる。

## 0. 現状（2026-08/12時点）

| 項目 | 状態 |
|---|---|
| 記事数 | `ai-tools` 10本（ranking 1・individual 5・faq 1・その他） |
| 公開状況 | `kenjatimejp.com`（Netlify）で公開済み。2サイト目 `drama-2026-summer` も同一ドメイン上に混在 |
| AdSense | `report` コマンドで広告収益記録日数0日＝**未同期**（審査未通過、または広告コード未設置の可能性） |
| Search Console | セットアップ手順は`docs/google-api-setup.md`に整備済み、登録状況は要確認 |

→ 現時点は「収益ゼロ〜審査前」のフェーズ。まずAdSense審査通過とアクセス基盤づくりが最優先。

## 1. 収益から逆算するPV目標

AdSense収益はおおよそ次の式で近似できる。

```
月間収益 ≒ 月間PV × RPM（1,000PVあたり収益） ÷ 1,000
```

RPMはジャンル・広告単価・季節・デバイス比率で大きく変動する。日本語コンテンツサイトの一般的な目安は以下。

| RPM水準 | 1,000PVあたり | 月5万円に必要なPV | 1日あたりPV目安 |
|---|---|---|---|
| 低（新規・低品質判定気味） | 200〜300円 | 約17万〜25万PV | 約5,700〜8,300 |
| 中（平均的な特化サイト・本サイトの想定ライン） | 400〜600円 | 約8.3万〜12.5万PV | 約2,800〜4,200 |
| 高（AI/SaaS比較など単価が乗りやすいジャンル・上位表示多数） | 800〜1,200円 | 約4.2万〜6.3万PV | 約1,400〜2,100 |

「AIツールランキング」はBtoB・SaaS寄りで広告単価が比較的高めに出やすいジャンルではあるが、初期は「低」水準からのスタートを想定しておくのが安全。
**目安として「月8万〜12万PVを1サイトで安定させる」を当面のマイルストーンに置く。**

## 2. フェーズ別ロードマップ

### Phase A（〜1ヶ月目）: AdSense審査を通す

AdSense審査に通らない限り収益化は始まらない。優先度最高。

- [ ] プライバシーポリシー・お問い合わせページの内容確認（`output/portal/content/privacy.md` / `contact.md` は生成済み。表現が定型文すぎないか、実運営者情報が書けるか確認）
- [ ] 記事本数を増やす。目安は独自性のある記事20〜30本以上（Googleの明示的な最低本数規定はないが、実務上はこの水準が通りやすい）
  ```
  /generate-article --site ai-tools --type individual
  /generate-article --site ai-tools --type related
  /generate-article --site ai-tools --type faq
  ```
- [ ] 生成のたびにSEO後処理とDB記録を実行
  ```bash
  python -m src.cli.main seo --site ai-tools
  python -m src.cli.main record --site ai-tools --scan output/ai-tools/content/
  ```
- [ ] `hugo && netlify deploy --dir public --prod` で公開を継続的に更新（`docs/サイト公開手順.md` 参照）
- [ ] https://www.google.com/adsense/ から審査申請。審査には数日〜数週間かかる
- [ ] 落ちた場合は「オリジナル性不足」「コンテンツ量不足」が主因になりやすいので、E-E-A-T要素（実体験・一次情報・デメリット記載）を強化して再申請

### Phase B（1〜3ヶ月目）: 広告掲載開始とインデックス整備

- [ ] 審査通過後、Hugoテンプレートの`<head>`と本文内にAdSenseコードを設置（CLAUDE.mdのPhase1範囲）
- [ ] Search Console にドメインプロパティ登録・サイトマップ送信（`docs/google-api-setup.md` 手順5）
- [ ] 主要記事をURL検査からインデックス登録リクエスト
- [ ] AdSense・Search ConsoleのOAuth連携をセットアップし、日次で数値を追えるようにする
  ```bash
  python -m src.cli.main sync-adsense --site ai-tools --days 3
  python -m src.cli.main sync-search-console --site ai-tools --days 3
  python -m src.cli.main report --site ai-tools
  ```
- [ ] 記事数を50〜100本規模まで積み増す（ranking・individual中心。カテゴリ網羅を意識）

### Phase C（3〜6ヶ月目）: PVを8万〜12万まで伸ばす

- [ ] `sync-search-console`で取れる掲載順位データを見て、**4〜20位で表示回数が多いのにクリックが少ない記事**を優先的にリライト・追記（伸びしろが一番大きい）
- [ ] 内部リンク（`src/seo/internal_links.py`）でランキング記事⇔個別記事の回遊を強化し、1セッションあたりPV（回遊率）を底上げ
- [ ] 週次で`report`の広告収益・検索指標を確認し、伸びていないカテゴリは切り捨てて伸びているカテゴリに記事を集中投下
- [ ] このフェーズで月1万〜3万円程度の収益が見え始めるのが目安（RPM次第で前後する）

### Phase D（6ヶ月目〜）: 複数サイト展開でスケール

1サイトだけでPVを青天井に伸ばすのは競合次第で頭打ちになりやすい。CLAUDE.mdのPhase3（マルチサイト）方針に沿って複数サイトに分散するのが本システムの強み。

- [ ] `config/sites/*.yaml` を追加するだけで新サイトを立ち上げられる（既に`drama-2026-summer`が2サイト目として存在）
- [ ] 例: 月2万円規模のサイトを3〜4個運用できれば合算で月5万円到達というポートフォリオ戦略の方が、1サイト依存よりGoogleアルゴリズム変動への耐性が高い
- [ ] **注意**: `drama-2026-summer`は`ai-tools`と`base_url`が同じ`kenjatimejp.com`になっている場合、`sync-adsense`/`sync-search-console`を両site_idに実行すると同じドメインの数値が二重集計されてしまう（`docs/google-api-setup.md`注意点参照）。収益を分けて追いたい場合はサイトごとにドメインを分離する

## 3. 計測・改善サイクル（Phase B以降、継続）

| 頻度 | やること | コマンド |
|---|---|---|
| 週次 | 広告収益・検索指標を同期して現状把握 | `sync-adsense --days 3` → `sync-search-console --days 3` → `report` |
| 週次 | 順位4〜20位・表示回数多いがCTR低い記事を洗い出しリライト候補にする | Search Console同期データを確認 |
| 月次 | サイト単位で収益トレンドを確認し、追加記事 vs 新サイト立ち上げを判断 | `report --site <site_id>` を全サイト分 |
| 月次 | `max_monthly_cost_usd`とコスト実績を突き合わせ、費用対効果を確認 | `report` のコスト欄 |

自動化: `.github/workflows/sync-metrics.yml` を有効化すればこの同期を毎日自動実行できる（Phase2でCI/CD整備予定、現状は手動運用）。

## 4. リスク・注意点

- **審査ステータスの罠**: OAuth同意画面が「テスト」のままだとリフレッシュトークンが7日で失効する。自動同期を長期運用するなら本番審査を通す必要がある（`docs/google-api-setup.md`参照）
- **コンテンツポリシー**: 自己クリック・クリック誘導は即アカウント停止リスク。生成記事のE-E-A-T要素（一次情報明記・デメリット記載）を崩さないこと
- **アルゴリズム変動**: 単一サイト・単一ジャンル依存はGoogleのコアアップデートで収益が急減するリスクがある。Phase Dの複数サイト展開はこのリスクヘッジも兼ねる
- **PV目標は不確実**: 上記の「8万〜12万PVで月5万円」はRPM中位帯を仮定した試算であり、実際のジャンル単価・競合状況で数ヶ月単位で前後する。四半期ごとに実績RPMで数値を更新すること
